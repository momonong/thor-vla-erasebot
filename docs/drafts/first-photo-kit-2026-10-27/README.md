# 首輪 8 張照片採集包

**這是一份待團隊採用的填寫包，尚未拍照、標註或執行辨識。**日期：2026-10-27（Asia/Taipei）。承接[參賽研究與準備稿](../../submission-plan.md)的首輪診斷設計，不改寫原計畫。目標是留下可追溯的原圖、人工答案與錯誤，8 張不是上限，也不能支持統計泛化或通過率承諾。

英文詞與紅、藍、綠、黑四色是工作假設，並非官方規則。這次只準備文件與空白資料表，沒有啟動照片採集、OCR、模型、硬體或實機控制。

## 三步使用

1. **採用前先填人力與物料。**閱讀下列拍攝卡、[採集模板](capture-template.json)、[評分模板](scoring-template.json)與[90 秒腳本](demo-90s.md)。確認後續操作範圍，填主責、覆核者與時間；在看系統結果前固定框配對方式、門檻及計分方式。
2. **後續獲授權採集時，逐卡留下原圖與實際條件。**填採集表的 `observed`；`planned` 保留設計。未達條件、重拍與失敗都記錄，不用漂亮照片覆蓋第一次。另一次拍攝需保留自己的檔案、時間與嘗試紀錄，必要時複製新增資料列，不能把多次嘗試藏成一張。
3. **先覆核人工答案，再填任何方法結果。**第一人依實際影像標註；第二人盡量先不看佈置答案，且兩人都應在看系統輸出前完成判讀。保留兩人原始判讀、分歧與裁決，在看系統輸出前凍結 `verified_reference` 版本，才記錄方法輸出及逐例計分；沒跑填 `null`／`not_run`，不要填假零。

兩份 JSON 是研究填寫模板，**不是 erasebot API 或 fixture**，不可直接交給現有 CLI。現有 CLI 的四個狀態只有 `selected`、`no_match`、`ambiguous`、`invalid_input`；本包的人工參考標籤不新增 CLI 能力。

## 共用拍攝與判讀規則

搜尋範圍預定為**本次完整板面**，實拍須全部入鏡；不要只裁到目標附近。保留未疊框、未改字的原圖與實際尺寸，不預填任何像素座標、板面大小、拍攝角度或設備型號。P01、P07、P08 使用同一塊未重寫的版面，規劃共用 `L01`／`G01`；若實際重寫或條件偏離，如實記錄，不能仍宣稱只變一因子。本輪全部是診斷資料，不切 train／test；後續擴充時同板重拍不得拆到兩邊。

**建議拍攝順序：P01 → P07 → P08 → P02 → P03 → P04 → P05 → P06。**這是順序提案，先完成 P01 同板的兩次重拍，再重寫其他版面，避免照卡號拍攝而失去基準。

**唯一／不存在需要完整搜尋證據。**若有未讀清區域可能藏著符合目標，或可能藏著第二個同字同色，不能只憑看清的部分標 `no_target`／`unique_target`。依原因標 `unreadable` 或 `unscorable`，或維持未覆核；P06 殘跡、P07 反光尤其要檢查。

下列詞區位置都是佈置提案，不是量測。每張實際詞的 ID、文字、顏色與框要另外由影像建立。`planned_word_id` 只指計畫位置，不能直接充作人工答案；未拍與未標註時 `words: []` 代表尚空，不代表白板已確認沒有文字。

## 標註與評分如何填

採集表每列分 `planned`／`observed`。`photo_file`、`image_size`、`capture_time`、`device`、`annotators` 目前全為 `null`，`words` 全為空陣列。拍攝後填原圖位置與實際條件；標註時複製獨立 `word_record_template` 至該圖 `words`，這個獨立範本本身不算觀測。`region_kind` 區分 `word`／`residue`／`uncertain`；`text_readability` 與 `color_readability` 分開填，看得懂字不代表看得清顏色。筆色意圖不是影像顏色答案；未知文字或顏色填 `null` 並留原因。人工覆核欄保留兩人原始判讀、分歧、裁決及版本。

座標只用影像 `image`／`px`：左上原點，x 向右、y 向下；框為 `[x_min, y_min, x_max, y_max]`，須符合 `0 <= x_min < x_max <= width` 與 `0 <= y_min < y_max <= height`。尺寸來自實際原圖；框值須有限且不能是 bool。此表沒有 mm、機座或手臂座標。

評分表已有 14 條指令。`planned_expectation` 是拍攝意圖；`verified_reference` 必須依實際原圖由兩人覆核，目標 ID 不從計畫直接複製。下列為人工評分標籤：

| 參考標籤 | 填寫依據 |
| --- | --- |
| `unique_target` | 完整搜尋範圍足以排除隱藏的第二目標，且只有一個可讀且符合文字／顏色者 |
| `no_target` | 完整範圍足以排除符合目標；覆核後 `target_word_ids` 填 `[]` |
| `ambiguous` | 確認至少兩個不同 ID 符合，不自行挑一個 |
| `unreadable` | 影像本身無法回答指令，文字／顏色或區域讀不清且可能影響判斷；未知 ID 用 `null` |
| `unscorable` | 缺圖、搜尋範圍不完整、標註分歧未解等證據不足以計分；記原因，不當成功或失敗分數 |

每例 `evidence_kind` 尚為 `null`；後續填 `manual`（人工）、`fixture_replay`、`photo_perception` 或 `future_robot`，各自保留來源。人工標記轉成 fixture 的選取結果只能標 fixture 回放，不能填成照片感知。`prediction`、`metrics` 目前皆 `null`；需要填寫時再複製頂層對應模板，每例 `score_details` 已留錯字、錯色、漏檢、多檢、位置與決策欄。分數須記所用照片與 reference 版本；換照片或答案版本就重新對應，不沿用舊分數當新版本成果。

- **詞與顏色：**文字 exact match；報可讀詞分母、正確、錯誤、漏檢及拒答，不只報有輸出的詞。顏色另列混淆與未知。
- **框與位置：**看結果前鎖定一對一框配對規則及門檻；報匹配框的定位誤差 px，漏檢、多檢另列，不能從位置分母消失。
- **指令：**以全部唯一可答題為分母，分列正確、錯選與拒答；選對須核對目標 ID，不能只看 `selected`。感知輸出 ID 須用固定框配對映射到人工 ID。不存在、歧義與畫質不足各類分開報；`invalid_input`／執行 error 記執行問題，不當正確拒答。
- **尚未評：**值填 `null`，不用 `0` 或 `100%` 代表待填。首次診斷不訂未經團隊採用的性能門檻；空模板沒有任何實測成績。

14 題總帳同時保留未跑、參考答案待覆核、可評、不可評與執行問題；各類計分的分母另列，不把沒有結果的案例靜默移除。

同一張圖有多道指令時，文字、顏色與框的感知成績不能因題數重複累計。以 `photo_id + photo_revision + method/run_id` 識別同次感知，供各題共用；感知以獨立影像／感知執行為分母，指令決策仍逐題計。另列實際執行與已評數，不把同一份證據引用多次當成新增樣本。

## 首輪驗收提案

建議驗收的是：8 張計畫都有已拍或未達成的明確狀態；實際原圖可追溯；每個詞與 14 例指令有人工覆核狀態；同板分組正確；方法若曾執行，輸出、錯誤、拒答與分母都保留。沒有照片或沒有方法結果時仍清楚標未完成，不以模板完成宣稱資料完成。

這輪的用途是找出讀字、辨色、框、選取或畫質問題。下一輪樣本擴充、重複次數與性能門檻仍待團隊固定；擦拭、校正與實機成效不在本包評分範圍。
