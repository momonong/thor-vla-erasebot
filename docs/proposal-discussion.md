先盤點四人的興趣、能力、時間與資源，再選值得探索的方向。企劃與 8 張診斷照片是建議起點；團隊可按結果加做，並非能力或工作量上限。

## A 我們想解決什麼問題？

本專案規劃讓使用者指定白板上的文字與顏色。系統應找出正確目標，將位置轉成可擦拭區域。長期目標包括完成擦除、檢查誤擦與殘字，並留下失敗原因。

近期希望寫出可信的參賽企劃，並找出最值得驗證的技術問題。四人可先共同回答：想達成什麼成果？各自對哪一段有興趣？現有經驗與器材能支持哪些探索？

| 狀態 | 本稿如何使用 |
| --- | --- |
| 已完成 | 有檔案、測試或來源可核對的成果 |
| 預計做到 | 目前建議的起點，尚未執行或量測 |
| 待確認 | 團隊選擇、官方規則或資源仍未確定 |
| 待團隊選擇 | 可以加做的探索，尚未成為交付承諾 |

本輪完成的是企劃討論文件。照片收集、辨識實驗與硬體整合，留待團隊選題及後續授權。

## B 現有基礎能支持哪一段？

**已完成：人工標記資料的離線目標選取。**既有專案使用 uv 與 Python 3.12 隔離環境。命令列工具讀取人工準備的指令與場景，再按文字、顏色精確比對。

| 已有證據 | 證明範圍 |
| --- | --- |
| 四種輸出狀態 | selected、no_match、ambiguous、invalid_input |
| 影像座標契約 | image／px；驗證影像尺寸及文字框 |
| 既有環境與全新環境各通過 21 項測試 | 輸入驗證、精確選取與診斷行為 |

證據可對照 README.md、docs/competition.md 與第一階段 verification.json。這是人工測試資料（fixture）的成果，尚未包含從照片讀字的能力。

```flow LR
指令與照片 -> 文字顏色位置 -> 目標選擇 -> 座標校正 -> 檢查後擦拭 -> 影像檢查與修正
```

候選流程中，目前只驗證人工資料到「目標選擇」這一段。感知、校正、控制與擦拭回饋尚待建立。模型輸出須經座標、工作區與動作檢查，才能進入控制端。

Thor、ARM64、JetPack、OCR、自然語言、模擬與實機均未驗證。專案名稱含 VLA，尚不代表團隊已選定此技術。

## D 第一輪 8 張如何產生可信證據？

**預計做到：以 8 張找出風險，保留成功與失敗。**有字的照片可先放 4–6 個詞。英文單字與紅、藍、綠、黑四色只是工作假設，並非官方範圍。

| 張數 | 拍攝內容 | 診斷重點 |
| --- | --- | --- |
| 3 | 清楚正面，分別變更書寫者、位置、字大小 | 基本讀字、辨色與定位 |
| 2 | 一張同字異色；一張同字同色出現兩處 | 選取是否正確、是否識別歧義 |
| 1 | 空白板帶淡殘跡 | 殘跡是否誤判；看不清就標不確定 |
| 1 | 反光或陰影擇一 | 光線造成的失敗 |
| 1 | 傾角或小字擇一 | 透視或解析度造成的失敗 |

每張保留原圖、尺寸、書寫者代號、版面及拍攝條件。每個詞記錄字串、墨色、框、目標 ID 與可讀性。由另一人覆核；有分歧先留下紀錄，再裁決答案。

每張再配固定指令與預期結果。可加入唯一目標、無目標與歧義題。同一張照片有多題時，同時報照片數與題數。

| 層級 | 報告內容 |
| --- | --- |
| 人工裁切讀字 | 完全正確詞數／可讀詞數；拒答不算讀對 |
| 人工裁切辨色 | 各色正確數／該色詞數；分歧另列 |
| 整張圖片找字 | 漏檢、多檢，以及配對框中心誤差 px；配對方式先固定 |
| 圖片＋指令選取 | 唯一正確、錯選、無目標、歧義、畫質拒答的件數及分母 |

唯一目標正確率以全部可唯一回答題為分母。錯選與拒答皆留在分母，不能用全拒答宣稱成功。無目標與歧義須核對狀態；畫質拒答不能算成無目標。

座標以影像左上為原點，x 向右、y 向下，單位 px。未校正前不換算毫米。8 張只作診斷，不承諾 90% 或泛化可靠；量化門檻待樣本與團隊討論。

診斷交付標準是 8 張全有標註、結果與失敗原因，不因出錯丟圖。擴充後按書寫者與版面分組，再劃分開發與保留集。同版重拍放同組，不當成獨立測試。
