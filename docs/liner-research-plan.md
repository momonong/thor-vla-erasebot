# 柔性襯材研究目標、開發與實驗

## 已確認定位

研究型提案：探索低成本單臂，能否依視覺狀態與真實示範完成柔性襯片的局部展開及對位。包裝前整備是研究情境，不是已驗證的產業痛點；目前沒有客戶訪談、採用承諾、省工、節拍或投資回收實證。

工作題名可先維持「柔性襯材自適應整備：SO-101 × Jetson Thor 包裝前襯片展平與對位」。若之後調整標題，應突出**有邊界的單臂操作研究**，避免暗示完整工廠自動化。題目與範圍不因 repo 的歷史白板名稱而改回擦拭。

## 核心研究問題

在單片、同材質、單一可見摺角與小幅偏位的限定條件下，使用每次操作後的視覺回饋及真實示範學習，能否提升整理成功率或降低人工接手，相較固定程序及明確的視覺規則基準？

可檢驗假說，不預先宣布成立：

- H1：起始狀態變化時，持續視覺回饋比固定程序更能修正錯誤。三方法均須用相同初態設計與重設規則驗證。
- H2：ACT 從真實示範學到的狀態—動作對應，在部分抓邊／提拉情境比手工視覺規則有效。若未優於基準，保留結果並分析資料與機械限制。
- H3：同一套策略可在指定 Thor 平台整合，且延遲、記憶體與動作更新頻率滿足後續實測需求。部署可行性與模型成功率分別驗收。

不把 H1/H2/H3 寫成已完成成果；30–50 段示範只作初始規劃，不保證學會。ACT 是可驗證的起點，不是宣稱已證明最優。LeRobot 官方以 ACT 作為入門候選，並說明影像／關節狀態到動作片段的形式；通用的示範量與訓練時間不能移作本題承諾。[ACT 官方文件](https://huggingface.co/docs/lerobot/act)

## 任務範圍與決策

**沿用既定核心：** 單支 SO-101 follower、單片無膠不透明襯材、平坦桌面、固定俯視相機；只處理局部可見摺角及小幅偏位。A 約 12×12 cm 是規劃核心，B 約 12×16 cm 是核心通過後的尺寸挑戰；材質、厚度與尺寸須機械試驗後凍結。leader 是示範裝置，非第二支工作臂。

**先解機械問題：** 夾爪能否在沒有人工預先提邊的條件下抓住材料；提拉後能否放下且重新觀察；單臂是否需要另一端持續張緊。GPT-Fabric 的真實實驗採 Kinova Jaco、改裝 KG-3 夾爪、RGBD 相機、泡棉工作面與 30.5 cm 方巾，其結果只能支持方法參考，不能證明 SO-101 與本案材料可行。[原論文 §7](https://arxiv.org/html/2406.09640v2)

**保留既定 protocol 0.1：** coverage≥0.95、IoU≥0.90、獨立摺角證據、零人工介入、最多6宏觀循環／90秒。此為研究目標而非官方要求或實測結果。若未來機械試驗促成門檻調整，需先說明原因與版本，禁止看完結果才降低標準。

**不要新增：** 揉團任意展平、多片分離、雙臂張緊、完整包裝線、零樣本跨材質、語音／大型語言規劃、完整布料物理模擬。這些都會分散目前可驗證的研究問題。

## 八章應回答的問題

| 既定章節 | 要讓評審理解的重點 | 準備的材料 |
| --- | --- | --- |
| 任務目標與應用情境 | 研究哪一種狀態變化，為何需要實際操作 | 120–180 字摘要；起始／操作／目標示意；明示需求尚未做現場驗證 |
| 任務拆解與成功標準 | 每一步可觀察什麼，何時成功或停止 | 抓邊、短提拉、放下、再觀察；現有 protocol；自重疊不能只靠俯視面積判定 |
| Robot Learning 方法 | 模型實際決定哪些動作，怎樣與基準公平比較 | ACT 的 observation/action、短段執行、狀態更新；固定程序、視覺規則、學習策略三者 |
| 資料採集與驗證 | 資料從哪裡來，怎樣避免洩漏或美化成績 | 真實示範規劃；episode／場次切分；48案／144列仍未執行；分組報告及未知值 |
| 硬體軟體與算力 | 工作站、Thor、相機與手臂各做什麼 | 系統流程圖；已存在／待取得資源；CPU環境不冒充CUDA訓練；不依賴未領取配額 |
| 實作時程與風險 | 哪一關失敗就應調整或停止投入 | 機械、資料、有限訓練、對照、部署關卡；官方節點不是已預約時段 |
| 既有成果與實作經驗 | 哪些是已做出的軟體，哪些仍需團隊實景證據 | 單筆與批次工具的分開證據；不累加重複測試；真實影片待使用者整理 |
| 團隊資料與來源 | 正式資料是否齊備，關鍵主張如何追溯 | 隊名／成員待補；公開來源；目前未送件；避免私人路徑與原始日誌 |

提案不需要把每個工程限制重複寫三遍。正文集中在研究問題、學習方法、可行路徑與圖表；可追溯證據與實作限制放在相應位置及證據清單。保留誠實界線，同時讓讀者能迅速理解要做什麼。

## 研究準備階段保留的開發順序（後續實驗見 Windows 交接）

1. 先修訂文稿與現況，讓評分敘事、來源、最新軟體成果及補件狀態一致。
2. 如需補軟體能力，優先考慮**影像／人工標註到既有評分器的資料入口**；目前批次工具仍只處理既有 JSON，不能從照片自己得到摺角或像素遮罩。先定資料契約與人工標註責任，再開發；不憑沒有照片的合成輸出宣稱感知成功。
3. 實機可用且另獲授權後，先機械關卡，再採集真實示範；不要先花大量算力訓練尚未證明能抓取的材料。
4. 真實資料穩定後才安排 ACT、三方法比較與 Thor 部署。完整布料模擬不是初選必要前置。

## 這輪準備完成後的討論入口

- 研究定位是否準確表達團隊想做的事，而不只是將產業詞彙貼上去。
- 最小展示是否仍保留「可見單角展開＋小幅對位」；是否有比單純多尺寸更有價值、但不擴大硬體風險的挑戰項。
- H1/H2 的比較，是否能回答學習方法的必要性；結果不如規則基準時如何誠實交代研究收穫。
- 哪些圖表進正文；哪些工程證據保留附件或證據表。

正式隊伍、影片與送件授權在資料準備完成後再處理；本階段不反覆催問，也不替使用者捏造。
